# 决策：探索式引擎目录与案例实验约定

- 日期：2026-08-23
- 提出：人（与 AI 对齐后确认）
- 状态：生效

## 背景

局面讲解的可计算规律尚未明确。需要通过“人工讲解 → 大模型反向提出假设 → 人工确认 → Node.js 编码”的长期过程摸索，不能过早用最终架构限制试验。

## 决定

1. `gomoku-coach-engine` 顶层采用 `src/`、`skills/`、`cases/`、`experiments/` 四类探索资产；`src/` 和 `skills/` 暂不预设子目录。
2. 拉菲引擎作为外部命令行程序调用。每次案例必须保留原始局面及拉菲生成的完整分析数据。
3. 每个案例使用唯一编号；`cases/<编号>/` 与 `experiments/<编号>/` 必须一一对应。
4. `cases/` 保存原始局面、拉菲完整分析数据、人工讲解；`experiments/` 保存硬性指标、所属大类型、AI 生成讲解。
5. 人工讲解按多图组织：每张图配一组按点击顺序展示的若干段讲解，当前图全部段落完成后才进入下一图。
6. 正式运行采用两次模型调用：第一次以硬性指标、总入口 skill、允许的分支 skill 名列表选择分支；第二次以硬性指标、总入口 skill、已选分支 skill 输出讲解。硬性指标必须由 Node.js 生成。

## 理由

案例及实验可完整回放，允许指标、讲解类别和 skill 内容持续推翻、比较和沉淀。把模型限制为提出并使用可验证的结构，避免不可追溯的模型判断混入硬性事实层。

## 影响

- engine README 与协作文档以拉菲 CLI、案例/实验对应和两次 skill 调用为准。
- 后续新建案例或实验必须遵守编号及讲解顺序约定。
- 具体硬性指标、讲解大类型及 skill 树均留待案例积累后再定。
