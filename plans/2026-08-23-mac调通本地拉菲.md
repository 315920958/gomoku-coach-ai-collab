# 开发任务 · 第一波：macOS 调通本地拉菲

> 阶段归属：对应 `plans/README.md` 的「阶段 1 · 确定拉菲 CLI 调用方式」。
> 技术方案权威说明见 `spec/05-拉菲迁移技术方案总览.md`。
> 本文曾由免费模型生成初稿，现已按 2026-08-23 的实际构建和初始化结果修订。

## 1. 本波目标与验收边界

本波只要求 macOS 本地初始化通过：

1. 分别构建 Apple Silicon `arm64` 与 Intel `x86_64` 二进制；
2. 配置与模型能成功加载；
3. Node.js 完成 `start() → begin() → setLine(19)`，收到 `OK`；
4. 固化一条可重复执行的健康检查命令。

初始化不做局面搜索。它能证明二进制、动态链接、配置、模型和基础协议可用，但不能证明 `think()`、INFO 解析、最佳点或天元坐标换算正确。真实计算另设后续验收，不再混入本波。

## 2. 实际版本与兼容决策

| 内容 | 实际版本 |
|---|---|
| Rapfi 源码 | `0.43.02`，commit `3c94c2a976f24a0dd1c5517623e9ab6fffe66bd7` |
| Networks | commit `e32ad77a5364363b3e3a02b3f9e8610ade19ea98` |
| 源码目录 | 项目根目录 `rapfi-source-latest/`（包含三个已初始化子模块） |
| macOS 模型 | `model210901.bin` + 四个 `mix9svq*.bin.lz4` |
| Windows 现有版本 | Rapfi `0.36.04` + `mix6` 模型，暂不改动 |

重要结论：Rapfi 二进制与模型/config 必须成套。现有 Windows 0.36.04 模型不能被 Rapfi 0.40/0.43 加载；当前公开源码历史又不包含 0.36.04 快照，因此 macOS 改用当前源码及其匹配的 Networks。Windows 与 macOS 目前并非同一 Rapfi 版本，跨平台分析结果暂不承诺逐值一致；后续应单独升级 Windows，使两端重新对齐。

## 3. 本地环境依赖

构建机器需要：

- macOS Apple Command Line Tools（`xcode-select -p` 可用，提供 Apple Clang）；
- Git；
- CMake，当前通过 `brew install cmake` 安装，实测版本 `4.4.2`；
- Node.js，用于运行项目调用层和健康检查，现场实测 Node.js `v26.0.0`；
- Apple Silicon 上若要运行 x86_64 产物，需要 Rosetta 2。

只运行仓库中已经打包好的当前架构版本时，不需要 Homebrew、CMake、Git 或编译器。Rapfi 产物仅动态依赖 macOS 自带的 `libSystem` 与 `libc++`；项目调用层仍需要 Node.js。Intel Mac 原生运行 x86_64 版不需要 Rosetta，Apple Silicon 原生运行 arm64 版也不需要 Rosetta。

## 4. 实际构建命令

Apple Silicon：

```bash
cmake -S rapfi-source-latest/Rapfi -B rapfi-source-latest/build-macos-arm64 \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_OSX_ARCHITECTURES=arm64 \
  -DNO_COMMAND_MODULES=ON \
  -DUSE_SSE=OFF -DUSE_AVX2=OFF -DUSE_AVX512=OFF \
  -DUSE_BMI2=OFF -DUSE_VNNI=OFF \
  -DUSE_NEON=ON -DUSE_NEON_DOTPROD=ON
cmake --build rapfi-source-latest/build-macos-arm64 -j 8
```

Intel：

```bash
cmake -S rapfi-source-latest/Rapfi -B rapfi-source-latest/build-macos-x64 \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_OSX_ARCHITECTURES=x86_64 \
  -DNO_COMMAND_MODULES=ON \
  -DUSE_SSE=ON -DUSE_AVX2=ON \
  -DUSE_AVX512=OFF -DUSE_BMI2=OFF \
  -DUSE_NEON=OFF -DUSE_NEON_DOTPROD=OFF
cmake --build rapfi-source-latest/build-macos-x64 -j 8
```

默认产物名是 `pbrain-rapfi`。部署后统一沿用项目调用契约名 `pbrain-rapfi_avx2`；arm64 文件名虽然含 `avx2`，实际是 NEON/DotProd 构建。

## 5. 部署结构

```text
gomoku-coach-engine/rapfi/
├── macos-arm64/
│   ├── pbrain-rapfi_avx2
│   ├── config.toml
│   ├── config_nonnue.toml
│   ├── model210901.bin
│   └── mix9svq*.bin.lz4（4 个）
└── macos-x64/
    └── 与上面同构
```

`src/rapfi/analyze.js` 按 `process.platform + process.arch` 自动选择目录。`spawn` 的 cwd 固定为二进制目录，使 config 中的模型相对路径可用。

## 6. 初始化健康检查

原生当前架构：

```bash
cd gomoku-coach-engine
npm run rapfi:healthcheck
```

显式检查另一架构或自定义二进制：

```bash
RAPFI_PATH=/绝对路径/pbrain-rapfi_avx2 npm run rapfi:healthcheck
```

成功标志为 `RAPFI_INIT_OK`。检查内部会启动进程、等待 evaluator 加载、发送 `start 19`、等待 `OK`，随后发送 `END`；不调用 `think()`。
