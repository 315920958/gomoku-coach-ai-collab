> 阶段归属：对应 `plans/README.md` 的「阶段 1 · 确定拉菲 CLI 调用方式」。
> 技术方案权威说明见 `spec/05-技术方案总览.md`（本文步骤以该文为准）。

## 1. 目标

在 macOS（Apple Silicon, arm64）上完成：

1. 从 `dhbloo/rapfi` 开源源码构建出原生二进制，放入 `gomoku-coach-engine/rapfi/macos/`。
2. 配齐模型与 config（跨平台通用，复用 windows 目录的同款）。
3. 用 `src/rapfi/analyze.js` 跑一次真实棋谱，能正确返回**天元坐标系**的 `answer` 与 `info`。
4. 把二进制 + 调用代码提交到 `develop`。

完成后，macOS 协作者 `git pull` 即可本地调用拉菲，无需任何额外下载。

## 3. 执行步骤

1. **确认前置就绪**：`cmake --version` 可用；`rapfi-build/CMakeLists.txt` 存在且 `rapfi-build/Networks/` 权重已拉全。
2. **构建 macOS 二进制**（Apple Silicon 用 NEON 指令集）：
   ```bash
   cd /Users/user/Documents/dev/nodejs/rapfi-build
   cmake -B build -DCMAKE_BUILD_TYPE=Release -DUSE_NEON=ON -DUSE_NEON_DOTPROD=ON
   cmake --build build -j
   ```
   找到构建产物（默认名可能非 `pbrain-rapfi_avx2`），重命名为 `pbrain-rapfi_avx2` 并放入：
   `gomoku-coach-engine/rapfi/macos/pbrain-rapfi_avx2`。
3. **复制模型与 config**（跨平台通用，从 windows 目录取同款）：
   将 `rapfi/windows/` 下的 `config.toml`、`config_nonnue.toml`、`model210901-e05000.bin`、5 个 `mix6*.bin.lz4` 复制到 `rapfi/macos/`。
4. **赋予可执行权限 + 解除 Gatekeeper 拦截**：
   ```bash
   chmod +x rapfi/macos/pbrain-rapfi_avx2
   xattr -d com.apple.quarantine rapfi/macos/pbrain-rapfi_avx2 2>/dev/null || true
   ```
5. **写验证脚本**：在 `examples/` 或临时脚本调用：
   ```js
   import { analyze } from '../src/rapfi/analyze.js';
   const r = await analyze('0_0;1_1;0_-1', { line: 15, bestn: 3, timeout: 500 });
   console.log(JSON.stringify(r, null, 2));
   ```
6. **跑验证**：确认输出 `answer` 为天元坐标、`info` 含评估值与深度、`success:true`，且坐标换算正确（可与已知局面手算核对）。
7. **提交 develop**：
   ```bash
   git add rapfi/macos src/rapfi package.json package-lock.json
   git commit -m "feat: 接入拉菲调用入口（ESM 多平台），构建 macOS 二进制"
   git push origin develop
   ```

## 6. 风险与对策

| 风险 | 对策（详见 spec/05 §8） |
|---|---|
| Gatekeeper 拦截未签名二进制 | `xattr -d com.apple.quarantine` + `chmod +x` |
| 构建产物名非预期 | 构建后检查实际文件名，重命名为 `pbrain-rapfi_avx2` |
| 权重子模块克隆不全 | 直接复用 windows 目录的模型（跨平台通用），不依赖源码子模块 |
| 进程卡死 | `analyze.js` 已有超时兜底（timeout+5s 强杀） |
