# 术语表

> 统一定义，防止「此引擎非彼引擎」这类歧义。凡文档 / 对话中出现下列词，一律按此表理解。

| 术语 | 含义 |
|---|---|
| **gomoku-coach** | 五子棋教练系统总名（产品 / 系统层面）。 |
| **gomoku-coach-ai-collab** | AI 协作文档仓。定「人 ↔ AI」交互规范、描述整体项目结构；不写代码。 |
| **gomoku-coach-engine** | 解说引擎，当前唯一的代码项目。探索链路：调拉菲 CLI → Node.js 硬性指标 → skill 路由与解说。 |
| **拉菲引擎 / 胜率计算引擎** | 底层、真正计算胜率和最佳路线的外部引擎；本项目通过命令行调用它。 |
| **硬性指标** | 只能由本项目 Node.js 代码从拉菲输出提炼出的、可复现和可追溯的结构化事实/信号。具体字段通过案例逐步确认。 |
| **案例** | 一个编号局面及其原始局面、拉菲完整数据、人工讲解；位于 engine 仓的 `cases/`。 |
| **实验** | 与案例同编号的硬性指标、所属大类型和 AI 生成讲解记录；位于 engine 仓的 `experiments/`。 |
| **总入口 skill** | 第一次调用使用的 skill：在限定的分支 skill 名中选择本次讲解路子。 |
| **分支 skill** | 第二次调用使用的 skill：基于硬性指标和已选路子，生成面向用户的讲解。 |
| **表现层 / 前端**（未来） | 面向用户、展示教练建议的界面层。 |
| **后端**（未来） | 调取 `gomoku-coach-engine` 的服务层。 |
| **对话交接文档** | `handoffs/` 下的文档，一段对话收尾时写，供下一段对话接力。 |
| **决策记录** | `decisions/` 下的文档，记录重要决定及其理由。 |

## 易混点

- **「引擎」出现两次**：`gomoku-coach-engine`（解说引擎，本项目）≠ 拉菲引擎（底层算胜率和最佳路线，外部）。
- **项目名即代号**：本项目不使用额外代号，一律以真实仓库名指代，避免多一层映射（见 `decisions/2026-08-23-目录结构与命名定调.md`）。
