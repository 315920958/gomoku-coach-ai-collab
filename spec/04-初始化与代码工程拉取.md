# 04 - 初始化与代码工程拉取

> 本文档是「AI 自动补齐开发环境」的操作依据。
> 任何人把本协作仓（`gomoku-coach-ai-collab`）clone 下来后，AI 据此自动把清单里的**所有代码工程**补齐到本地、统一切到开发分支并拉取最新代码，使新环境一次到位。

## 1. 适用范围

- 本协作仓（`gomoku-coach-ai-collab`）是**人先 clone 的入口**，不在此清单内。
- 「代码工程」指会写代码的仓库（目前仅 `gomoku-coach-engine`，将来每增加一个就往 §2 清单里加一行）。
- 所有代码工程统一遵循 `develop / test / production` 三分支规范（见 `spec/01-项目结构总览.md` 的「代码项目分支规范」一节）。本初始化只负责把代码工程拉到**开发分支 `develop`**，其余分支按需再切。

## 2. 代码工程清单

| 工程名 | 本地目录（与本仓同级） | Git 远程地址 | 默认分支 | 说明 |
|---|---|---|---|---|
| gomoku-coach-engine | `gomoku-coach-engine` | `git@github.com:315920958/gomoku-coach-engine.git` | `develop` | 解说引擎（调拉菲 CLI → Node.js 硬性指标 → skill 讲解） |

> 新增代码工程时，复制上表一行填入即可。AI 启动时只认这张表，不靠记忆。

## 3. AI 执行步骤

对 §2 清单中每一项，依次执行。约定：本协作仓所在目录为 `<ROOT>`，各代码工程 clone 到 `<ROOT>/<本地目录>`（与本仓同级）。

**第 1 步：逐工程补齐**

对每个工程（以 `gomoku-coach-engine` 为例，目录记为 `DIR`）：

```bash
# 1. 若目录不存在则 clone，存在则跳过 clone
if [ ! -d "DIR" ]; then
  git clone git@github.com:315920958/gomoku-coach-engine.git DIR
fi

# 2. 进入目录，切到开发分支并拉取最新
cd DIR
git checkout develop
git pull origin develop
cd ..
```

> 说明：
> - 若本地尚无 `develop` 分支但远程有，先建跟踪分支再拉：
>   `git checkout -b develop --track origin/develop && git pull origin develop`
> - 若 `develop` 本地已存在，直接 `git checkout develop && git pull origin develop` 即可。
> - 用 `if [ ! -d ... ]` 判断，重复执行安全（已 clone 的不会覆盖、不会报错）。

**第 2 步：汇报结果**

完成后，向用户输出每个工程的：目录、当前分支、最新 commit 短哈希。例如：

```
gomoku-coach-engine  →  develop  (fa7df00)  已是最新
```

若某项 clone 或 pull 失败，单独列出失败项与错误信息，不继续执行其余项以外的动作。

## 4. 约定与边界

- **只读式拉取**：初始化阶段只做 clone / checkout / pull，不切换其他分支、不 merge、不 push、不改代码。
- **分支只到 develop**：test / production 由后续按需切换，不在初始化阶段处理。
- **清单唯一真相**：代码工程列表以 §2 表格为准；新增工程必须同步更新本表，AI 不自行猜测仓库地址。
- **与人-AI 对话规范一致**：本动作属于「补齐环境」，不涉及业务改动，无需单独授权即可执行；但若 clone 到非 `<ROOT>` 同级目录、或要改远程地址，需先与用户确认。
