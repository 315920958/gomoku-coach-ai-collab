# 人-AI 对话规范

> 人和 AI 在这个项目里怎么沟通。这是「规矩」，不是建议——新对话开局应先读本文。

## 核心原则

1. **单一职责会话**：一个对话只干一类事（写文档 / 写代码 / 排查问题分开）。不偏题、不擅自切换角色。
2. **先对齐，再动手**：动手建文件、改结构、写代码前，先复述理解、确认方案。尤其涉及目录 / 命名 / 架构的改动。
3. **改动 / 部署前先确认**：任何涉及服务器、数据库、线上环境、git 推送的动作，必须拿到明确授权再执行；模糊口吻不等于授权。
4. **结论留痕**：讨论出的结论（结构、命名、架构定调）必须写入 `spec/`、`decisions/`、`handoffs/`，不只在聊天里说完就过。
5. **术语一致**：用真实项目名，不发明代号；「引擎」出现时点清是哪一层。
6. **阶段性开新对话**：和大模型对话宜保持轻快，过一个阶段就开新对话；旧对话收尾时写 `handoffs/` 交接。

## 一个标准回合长这样

1. 人说需求 / 背景。
2. AI 复述理解（用简单的话），指出歧义点，对齐。
3. 双方确认方案。
4. AI 动手，并把结论写入对应文档。
5. 一段收尾 → 写交接文档，供下一段接力。
